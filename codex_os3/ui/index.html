Other computers join OS3 with rabbit's own node installer. They don't need this router: model calls always go through the one device you picked; tasks can still run on every node.

Get help · Self fix

Describe what goes wrong. The router adds its own diagnostics (checks, recent errors, the rabbit-agent log; never your messages or keys) and asks gpt-6-luna for the cause and a fix. This uses a little of your Codex limit. Fixes only run when you click them.

Report a problem

Something broken or odd? Tell the developer. It's sent anonymously (no messages from OS3, no names, no keys) and becomes a GitHub issue.

Common problems

  • OS3 says the device is offline or the endpoint is unreachable: the device in OS3 must be the machine this router runs on, and the endpoint must end in :/v1 (the Ollama preset puts 11434 there).
  • “This model did not make a tool call” when saving: check that the API key is the router's, then save again (OS3's test is a live call; one retry is normal).
  • You changed or reinstalled something: a connection can't be edited in OS3. Delete it and add it again (Setup → “Set up again”).
  • “Usage limit reached”: your ChatGPT or Claude plan's limit; the Dashboard shows when it resets.

Models

OS3 sends one model for everything; the router sees who is asking and uses these. Small = the chat you talk to · Standard = workers doing tasks (shell, files, computer use) · Background = memory and review (runs often: keep it light). Effort: OS3's own sliders decide it for Small and Standard; the effort here is used for Background and whenever OS3 sends none.
